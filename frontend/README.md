# Radio Quantica: Next.js React App

This is the front end code for the Rádio Quântica website written in Next.js and styled with Tailwind CSS. The service is deployed on Vercel.

Content (shows, news, about/donate pages, etc.) is fetched at build and request time from the Payload CMS backend in `../api` over GraphQL, using types generated by GraphQL Codegen (see below). Live audio/schedule data comes from a Libretime instance, and live video status from an Owncast instance — see the root [README](../README.md) for how those integrations work.

## Getting Started

You'll need the `api/` backend running locally (or point `NEXT_PUBLIC_SERVER_BASE_URL` at a running instance) — the frontend fetches its GraphQL schema and content from it both at build time and at runtime.

Run `npm install`, then `npm run dev` (or `npm run dev:local` / `npm run dev:prod` to also set `NEXT_PUBLIC_SERVER_BASE_URL` for you). This also starts `graphql-codegen --watch` alongside `next dev`, so `lib/gql/types/` stays in sync with your query changes.

> The GraphQL Codegen CLI requires Node ≥22.13. If your default Node is older, run under a newer version (e.g. via `nvm use 22`) before `npm run dev` / `npm run generate`.

Open [http://localhost:3001](http://localhost:3001) with your browser to see the result (the dev server runs on port 3001, not 3000, so it doesn't collide with the API).

You can start editing the page by modifying `pages/index.tsx`. The page auto-updates as you edit the file.

If you change or add a `graphql(...)` query/mutation in `lib/gql/documents/queries.ts`, run `npm run generate` to regenerate `lib/gql/types/` (or rely on the `--watch` process started by `npm run dev`).

The `pages/api` directory is mapped to `/api/*` and holds [API routes](https://nextjs.org/docs/api-routes/introduction) instead of React pages — currently just `pages/api/revalidate.ts`, an on-demand ISR revalidation webhook gated by a `REVALIDATION_TOKEN` secret, used to bust cached pages when content changes in the CMS.
